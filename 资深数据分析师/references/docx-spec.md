# 报告规格（JSON → Word）与排版标准

`scripts/build_report_docx.py` 接收一份 JSON 规格，直接产出成品 .docx。先写规格、再跑脚本，比直接手写 python-docx 稳定得多。

## 1. 运行

```bash
python3 scripts/build_report_docx.py --spec report.json --out "<主项目目录>/XX分析报告_2025年1-9月.docx" [--theme blue|red]
```

- `--theme` 优先级最高；其次读规格里的 `"theme"`；都没有时按蓝白。
- 依赖缺失先装：`pip3 install python-docx matplotlib`。
- 脚本只负责排版与图表渲染，**所有数字与结论由你写进规格**，脚本不会计算任何业务指标。
- 输出路径用主项目目录（`Main project directory`），文件名写业务 + 时间范围，例如 `门店销售分析报告_2025年1-9月.docx`。

## 2. 规格骨架

```json
{
  "title": "区域门店销售分析报告",
  "subtitle": "数据区间：2025年1—9月｜1,286 行明细、8 个字段",
  "theme": "blue",
  "summary": "这张表是……，覆盖……，其中……三项指标已算好。",
  "sections": [
    {
      "heading": "一、数据概览",
      "paragraphs": ["正文段落，支持 **加粗**。"],
      "blocks": [
        {"type": "table", "caption": "表1 字段清单与口径",
         "header": ["字段", "类型", "说明"],
         "rows": [["销售额", "原始明细", "含税，单位：元"]],
         "col_widths": [4.2, 3.2, 8.2],
         "note": "数据来源：XX表（用户提供）。"},
        {"type": "chart", "caption": "图1 月度销售额走势：6 月下滑、7 月起修复",
         "kind": "line", "unit": "万元", "time_range": "2025年1—9月",
         "source": "门店销售明细表",
         "x": ["1月", "2月", "3月"],
         "series": [{"name": "销售额", "values": [1180, 1240, 1310]}]},
        {"type": "bullets", "items": ["**要点**：说明。"]},
        {"type": "callout", "label": "口径提示：", "text": "销售额含税。"},
        {"type": "subheading", "text": "（一）分区域表现"}
      ]
    }
  ],
  "appendix": {"paragraphs": ["字段口径与剔除规则说明。"]},
  "usage_note": "把你的表格发来，告诉我用红白还是蓝白（不说明就默认蓝白），我直接给你一份能用的 Word 分析报告。",
  "footer": "资深数据分析师 · 数据分析报告"
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| title | 是 | 报告主标题，别用"数据分析报告"这种空标题，写业务主体 |
| subtitle | 建议 | 时间范围 + 数据量 + 字段数，一行说清覆盖范围 |
| theme | 否 | `blue`（默认）/ `red` |
| summary | 是 | 读表摘要（写在一句话内，含业务、时间、行数、哪些指标已算好） |
| sections | 是 | 五段，`heading` 严格用「一、数据概览」…「五、结论建议」 |
| appendix | 否 | 自动加"附：数据说明"，放口径、剔除规则、数据来源 |
| usage_note | 建议 | 自动加"使用说明"段，放一句话使用说明 |
| page_break_before_body | 否 | true 时正文从新页开始，报告较长（≥4 页）才开 |

block 类型：

- `paragraph`：`text`，支持 `**加粗**`；`"indent": false` 可取消首行缩进（图表后紧跟的说明句用）。
- `bullets`：`items` 数组，自动加点号与悬挂缩进。**每条一句话结论 + 数据 + 动作**。
- `subheading`：段内小标题（如"（一）分区域表现"）。
- `table`：`caption` 显示在表上方（中文规范表题在上）；`note` 在表下方放来源/口径。
- `chart`：见下节；`caption` 显示在图下方。
- `callout`：浅色提示框，用于读表摘要、口径提示、还需补充的数据。

## 3. 图表规格

| kind | 必填字段 | 适用 |
|---|---|---|
| `line` | `x`、`series[{name, values}]` | 趋势。时间点 ≥ 6 才画折线 |
| `bar` | `categories`、`values`；`orientation: "h"/"v"` | 排行。Top 5—8，其余合并"其他" |
| `donut` | `categories`、`values` | 占比。类别 ≤ 6，超过先合并 |

公共字段：`caption`（写**结论句**，不是"销售额走势图"）、`unit`（万元/%/人/单）、`time_range`、`source`。

- `unit` 含 `%` 时图内百分比按 1 位小数显示；否则数值自动按 万/亿 缩写。
- 脚本会在图下自动补一行小字：`单位：X｜时间范围：Y｜数据来源：Z`，不要在 caption 里重复三遍。
- 数据点少于 3 个、或只有两行对比 → 改用 `table`，不画图。
- 涨跌不在图里硬编码颜色：折线单序列统一用主题色，涨跌在正文文字里写清（"上涨 12.4%"/"下降 18.3%"），需要颜色强调时用 `**` 加粗 + 文字说明即可。

## 4. 排版规格（已内置，改版时按此表改脚本常量）

| 元素 | 规格 |
|---|---|
| 页面 | A4，上下 2.4/2.3 cm，左右 2.7 cm，可用宽 15.6 cm |
| 主标题 | 微软雅黑 22pt 加粗，主题色；下方 1.5pt 分隔线 |
| 副标题 | 10.5pt 灰色 `808080` |
| 一级标题（五段） | 微软雅黑 16pt 加粗，主题色，段前 18pt / 段后 8pt，浅色下边框 |
| 正文 | 宋体 12pt（小四），行距 1.4，首行缩进 2 字符，两端对齐，段后 6pt |
| 表头 | 主题色底 + 白字 10pt 加粗，跨页重复表头 |
| 表格正文 | 10pt，首列左对齐、数值列居中，边框 `BFBFBF` 细线 |
| 图表 | 宽 15.6 cm 居中；图题 9.5pt 加粗，图下灰色注脚 8.5pt |
| 页脚 | 右对齐"资深数据分析师 · 数据分析报告 ｜ 第 X 页" |
| 色系 token（蓝白） | primary `1F4E79`、accent `2E75B6`、light `EAF1F8` |
| 色系 token（红白） | primary `B42318`、accent `D9453D`、light `FBEAE7` |
| 涨跌 | 涨 `C00000`（红）、跌 `1E7B34`（绿） |

全篇禁止表情符号（emoji）；数字统一 Times New Roman。

## 5. 常见错误

- `heading` 自己另起名字（如"业务概览"）→ 必须用固定的五段命名。
- caption 写成"XX趋势图"，没结论 → 改成"6 月单月下滑 12%，7 月起逐月修复"。
- donut 塞了 8 个类别 → 合并成 ≤6，剩余进"其他"。
- 用 `bar` 画 20 个门店 → 只留 Top 6 + "其他 N 家"。
- 规格里出现表里没有的数字 → 一律改为"数据不足"字样，不许占位假数。
- 一个 block 里塞两张图 → 一张图只讲一件事，拆成两个 block。
