# 阶段三 · 统计需求挖掘（挖掘清单 → 一句指令 → 公式落地）

本阶段只做**统计计算**（求和、平均、计数、分组、占比、排名、比值、对比），不做出图、不做结论判断。分两步：先挖掘（只读），用户确认后再落地公式。

## 一、判定走哪一版

| 材料 | 走哪版 | 读哪个文件 |
| --- | --- | --- |
| 1 文件 1 sheet | 单表版 | `references/single-table-prompt.md` |
| 2+ 文件，或 1 文件多 sheet | 多表版 | `references/multi-table-prompt.md` |
| 业务表 + 对照/字典表（城市-大区、商品-类目） | 多表版（查字典补字段） | 同上，说清"这是查字典，不是汇总" |
| 多 sheet 只是同业务分月/分店 | 多表版（纵向合并） | 同上，先提醒统一字段名 |

判定依据是**实际上传的文件与 sheet 数**，不是用户口头说"就一张表"。先跑 `scripts/inspect_workbook.py` 看 sheet 数、表头行、类型、空值、唯一键、底部合计行。

## 二、挖掘输出（四块，按顺序）

1. **读表摘要**：一句话说清字段、业务类型（销售/工资/新媒体/库存…）。
2. **挖掘清单**：值得统计的业务数据分几类，大白话可选清单（赚没赚、花没花、值不值 / 谁最好、漏在哪）。
3. **写好的【做统计】指令**：整句可直接复制，另主动多给一版进阶写法（占比/排名/比值/同比/双维度交叉），标明哪版够用、哪版多看一点。
4. **一句话使用说明**：复制发回来即出结果，不用碰公式。

指令规矩：只写计算动作；字段全部来自真实表；多表指令必须含"哪几张表 + 按哪个字段关联 + 算什么指标"；末尾固定加"结果用公式写进原表副本新 sheet，原表不动，后续改数自动重算"。

## 三、落地（用户确认后）

- 先读 `sheet` skill（若环境安装了 sheet skill，按其引擎/备份/交付规则执行；未安装时直接用 openpyxl）。
- `cp 原表.xlsx 原表_统计结果.xlsx`，只在副本新增 sheet，原 sheet 名称与顺序不变。
- 写 `spec.json`（四种 layout：`group` / `total` / `join` / `combine`）→

```bash
python3 scripts/add_stats_sheet.py spec.json
python3 scripts/add_stats_sheet.py --check "原表_统计结果.xlsx"
```

- spec 结构、指标类型、公式速查、报错处理见 `references/formula-recipes.md`。
- 结果必须满足：每个指标是公式不落死值；引用范围能随数据增长（表底有合计行时用 `data_range` 限定）；新增 sheet 用人能看懂的业务名；底部写口径（数据源/表头行/数据区/分组/算法/生成时间）；排名用 `RANK`、分组最值用 `_xlfn.MAXIFS`，不手写 `XLOOKUP`。
- 想让预览也能看到数字：`bash scripts/recalc_values.sh "原表_统计结果.xlsx"`。
- 改口径就改 spec 重跑，不在结果 sheet 里手改公式。

## 四、交付话术

说清三件事：新增了哪些 sheet、每张算什么口径、以后改原表数据会自动重算。不把每行数字抄进回复。
